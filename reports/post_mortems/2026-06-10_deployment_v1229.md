## What shipped in v1.2.29

### Content-addressed skip (ADR-041)

The dominant cost reduction. Assembly (previously ~3h on server) and zarr export (previously ~2h on server) now check SHA-256 digests of all inputs against `provenance.json` from the previous run. If all digests match and the output file is intact, the step records `outcome: "unchanged"` in the ledger and exits in seconds.

Five correctness gaps were found and fixed before shipping:

- **C-259:** Static/admin Parquet directories were not digested — false skip on GAUL or static variable updates.
- **C-260:** Key-set comparison was subset-only — removing a source (e.g., dropping `--acled-grid`) would not trigger rebuild.
- **C-261:** No ledger entry on skip — temporal gap in audit trail (operator can't distinguish "ran, nothing changed" from "didn't run").
- **C-262:** Output integrity not verified — truncated `grid.npy` (from crash or disk-full) served indefinitely.
- **C-263:** `mkdir` in `finally` block could mask original exception on disk-full.

All five are resolved. The skip module lives in `datafactory_provenance/skip.py` with `SkipVerdict` dataclass, `check_assembly_skip()`, and `check_export_skip()`. 209 lines of unit tests + 366 lines of integration tests.

### Source-digest gates (C-253, C-255)

Export scripts now verify `grid.npy` digest before exporting. The ACLED dedup incident vector (correct grid, stale zarr) is structurally blocked. `check_export_freshness()` now reports content freshness separately from time freshness.

### SHDI pipeline wiring (C-265)

`harvest_shdi.py` was integrated into the codebase but never added to `refresh_pipeline.sh`. Status page showed SHDI as permanently RED. Fixed by adding the harvest call at line 173. First successful SHDI harvest ran during this deployment.

### Partition drift fix (C-264)

`PARTITIONS` in `defaults.py` had drifted from `views-models`. Four alignment tests were failing. Boundaries updated to match all 5 integrated models.

### healthchecks.io monitoring (C-131)

External monitoring configured end-to-end:
- healthchecks.io check: `views-datafactory pipeline refresh`, 30-day period, 48-hour grace.
- `HEARTBEAT_URL` set in `~/.profile` for `views-deploy`.
- Ping confirmed at 2026-06-10T15:33:42 UTC (Ping #2 — Ping #1 was the manual test during setup).
- ADR-018 updated with service choice and configuration.
- Deployment guide updated with section 4.6 (setup + troubleshooting).

### try/finally for complete ledger coverage

Assembly and export scripts now wrap the entire work section in `try/finally`. Every exit path — `return`, `raise`, uncaught exception — writes a ledger entry. Previously, crashes or early returns left no provenance record.

### Risk register curation

15 new entries from the deep test review (C-267 through C-281). 4 entries demoted to tech-debt backlog (C-121, C-272, C-277, C-278). 2 disagreements resolved (D-34, D-36), 1 new (D-37). Register now at 281 IDs, 210 resolved, 67 open.

## Performance analysis

### Where the 4 hours went

The 65% duration reduction is primarily from two mechanisms:

1. **Content-addressed skip (ADR-041):** Assembly and zarr export check input digests against the previous `provenance.json`. If all digests match and the output is intact, the step skips in seconds. On the Hetzner server (CPX32, 4 vCPU, 8 GB RAM), assembly previously took ~3 hours and zarr export ~2 hours — together accounting for ~80% of the v1.2.26 pipeline duration.

2. **Harvest caching (ADR-032):** Most sources were already cached from the v1.2.26 run. UCDP (last harvested 2026-04-26), GHS-POP (2026-05-20), GHS-BUILT-S (2026-05-23), V-Dem (2026-05-28), PRIO-GRID (2026-03-31) all returned cached results immediately.

### Duration history on Hetzner

| Version | Date | Features | Duration | Notes |
|---------|------|----------|----------|-------|
| v1.2.20 | 2026-05-24 | 53 | 12,351s (3.4h) | First full deploy with GHS-BUILT-S |
| v1.2.21 | 2026-05-25 | 53 | 14,269s (4.0h) | Cold OS cache after reboot |
| v1.2.26 | 2026-06-02 | 75 | 21,965s (6.1h) | +22 V-Dem features, +41% grid size |
| **v1.2.29** | **2026-06-10** | **75** | **7,631s (2.1h)** | **Content-addressed skip active** |

The v1.2.20 → v1.2.26 growth (3.4h → 6.1h, +79%) tracked the grid size increase (25.1 GB → 35.5 GB, +41%). The v1.2.29 reduction breaks this trend: same grid size, 65% less time. Future runs with unchanged inputs should be even faster (harvest caching warm, skip triggers immediately).

### Projected monthly cron duration

For a monthly cron run where only UCDP candidate/dot9 and ACLED have new data:
- Harvest: ~10 min (UCDP + ACLED fetches; 7 other sources cached)
- Consolidation + Viewpoint + Compilation: ~20 min (UCDP + ACLED paths only)
- Assembly: **full rebuild** (~3h on server) — because UCDP and ACLED digests changed
- Zarr export: **full rebuild** (~2h) — because assembly output changed
- Total estimate: **~5.5 hours**

The skip only saves time when no input data changes. Monthly runs will still be long because UCDP and ACLED always have new data. The skip pays off during: development deploys, code-only changes, re-deploys after bugs, and months where upstream sources are delayed.

## Deployment process

### What went well

1. **Zero obstacles.** v1.2.26 required 7 hours of debugging between "ready" and "running." v1.2.29 was running within 15 minutes of starting the deploy. The pre-deploy audit (test review, falsification, register curation) caught and fixed both bugs (C-264 partition drift, C-265 SHDI gap) before deployment.

2. **Operator stayed attached.** Previous deployments detached from the terminal and checked back hours later, missing failure output. This time the operator watched the full run, catching known anomalies in real time and confirming the health check results immediately.

3. **healthchecks.io works.** First deployment with external monitoring. Ping confirmed within 1 second of pipeline completion. The monitoring gap (C-131, open since 2026-04-22) is now closed.

4. **Status page is comprehensive.** All 9 sources visible, layer-by-layer status, clear green/N-A/missing indicators. SHDI correctly shows as harvest-only with downstream layers not yet integrated.

### What we'd do differently

1. **Add xfail to `test_version_not_already_tagged` after tagging.** Three falsification tests fail because v1.2.29 is already tagged. These are deploy-gate tests that correctly detect "this version was already shipped." They should be xfailed after the tag is created (like the deploy-tag gate test was) or restructured to check "tag exists AND tag commit matches HEAD" instead of "tag should not exist."

2. **Measure per-step durations.** The pipeline prints total duration (7,631s) but doesn't print per-step times. We can't determine from the output how long each step actually took, only that all passed. Adding `Step N completed in Xs` logging would let us build an accurate server-side performance profile without manual timing.

3. **Log content-addressed skip decisions explicitly.** When assembly or export skips, the pipeline output should show which digests matched and what was skipped. Currently the skip decision is logged to the ledger but the console output doesn't distinguish "assembly ran and produced identical output" from "assembly skipped because inputs matched." For a postmortem, we want to know which path was taken.
