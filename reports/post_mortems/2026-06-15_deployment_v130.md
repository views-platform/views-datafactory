## What shipped in v1.3.0

### SHDI downstream integration (PR #160)

The dominant new capability. SHDI (Subnational Human Development Index) data from the Global Data Lab is now compiled and assembled into the grid. The pipeline path is harvest → viewpoint → compilation → assembly, skipping consolidation (single periodic release, ADR-036).

- **4 new features:** shdi, healthindex, edindex, incindex (intensive indices bounded [0, 1])
- **Spatial coverage:** ~58,000 land cells (89.9% of land) via GDL-to-PRIO centroid spatial join
- **Temporal coverage:** 1990–2023 (34 years), broadcast to monthly resolution
- **NaN preservation:** ADR-042 — cells with no GDL region retain NaN, not interpolated
- **Grid step:** Step 9/14 in `refresh_pipeline.sh` (`run_shdi_pipeline.py --skip-to viewpoint`)
- **ADR-036:** SHDI source selection rationale documented

Supporting artifacts: ShdiViewpointConfig CIC, 665-line viewpoint test suite, 314-line compilation test suite, 14-panel visual audit report.

### Azores supplement (PR #163, ADR-043)

4 Azorean islands (Flores, Corvo, Graciosa, Santa Maria) were missing from GAUL 2024 boundaries. A curated GeoJSON supplement (`data/raw/gaul_admin/supplement_azores.geojson`) is now appended during GAUL harvest, adding 6 PRIO-GRID cells to the admin boundary set. The supplement is tracked in git and available on server after checkout.

### Bundled curated region: land_gaul (PR #161)

A precomputed set of 64,742 pgids representing the intersection of land cells and GAUL-covered territory. Bundled in `datafactory_query` for downstream consumers (views-postprocessing) that need a stable spatial footprint without importing spatial processing libraries.

### Cross-layer schema contract tests (PR #192, C-288)

Parametrized tests verifying that viewpoint output columns match compilation input expectations for all 6 sources (UCDP, ACLED, GHS-POP, GHS-BUILT-S, V-Dem, SHDI). Catches schema drift at test time rather than at runtime.

### Count conservation at consolidation and viewpoint boundaries (PR #192, C-258)

Conservation invariants (`input = output + discarded`) at ACLED consolidation, UCDP consolidation, ACLED viewpoint, and UCDP viewpoint boundaries. Extends ADR-040 upstream from compilation to cover the full path.

### Doc/code consistency fixes (PR #169)

Temporal module routing, source taxonomy (ADR-044: reference vs. feature sources), ACLED event_type_filter documentation aligned with code behavior.

### Risk register curation (PR #162, PR #192)

- 5 already-resolved concerns closed (C-264, C-282, C-283, C-284, C-285)
- 3 entries demoted (C-274, C-275, C-279)
- 8 entries clustered into causal groups
- 17 deferred tracking issues created on GitHub
- Register at 290 concern IDs, 224 resolved, 63 open (0 Tier 1, 6 Tier 2)

### Deploy preparation (PR #193)

Version bumped 1.2.29 → 1.3.0. Conditional xfail added to 3 version-tag tests that perpetually fail post-deploy (v1.2.29 postmortem item 1). Deploy readiness falsification tests added.

## Performance analysis

### Why 7.2 hours (vs. 2.1 hours for v1.2.29)

The v1.2.29 deployment benefited from content-addressed skip: grid shape was unchanged (75 features), so assembly and zarr export skipped in seconds. For v1.3.0, the grid shape changed from 75 to 79 features, which:

1. **Forced full assembly rebuild.** The skip logic (ADR-041) detected that the assembled grid would have 79 channels vs. the 75 in the existing provenance. Assembly rebuilt from scratch — the dominant cost (~3-4 hours on CPX32).
2. **Forced full zarr export.** The assembly output changed, so the zarr export digest comparison failed. Full export (~2 hours).
3. **Added SHDI compilation.** First-time viewpoint build + compilation for SHDI data. Estimated ~10-15 minutes — a minor fraction.

The 7.2-hour total is consistent with pre-skip durations (v1.2.26 was 6.1h with 75 features; v1.3.0 has 79 features and ~6% more data).

### Projected monthly cron duration

For a monthly cron run where only UCDP candidate/dot9 and ACLED have new data (79-feature grid):
- Harvest: ~10 min (UCDP + ACLED fetches; 7 other sources cached)
- Consolidation + Viewpoint + Compilation: ~20 min (UCDP + ACLED paths only)
- Assembly: **full rebuild** (~4h on server) — UCDP and ACLED digests changed
- Zarr export: **full rebuild** (~2h) — assembly output changed
- Total estimate: **~6.5 hours**

The 1-hour increase over the v1.2.29 projection (5.5h) tracks the grid size increase (75→79 features, ~6% more data in assembly and export).

## Deployment process

### What went well

1. **Zero obstacles for the second consecutive deployment.** The falsification audit (`/falsify "we are ready to deploy"`) identified the 2 hard blockers (version not bumped, main not merged) and 1 soft finding (postmortem items not addressed) before deployment started. All were resolved in a single PR (#193) in under 30 minutes.

2. **Pre-deploy falsification works as a gate.** The audit caught what would have been a "why can't I create the tag" surprise at deploy time. The test stubs (`test_falsification_deploy_v130.py`) now encode these checks for future deployments.

3. **v1.2.29 postmortem "do differently" items addressed.** The xfail for version-tag tests (item 1) was implemented as a conditional xfail — the test runs normally pre-tag, xfails post-tag. Items 2 (per-step durations) and 3 (skip decision logging) were not addressed because the pipeline script changes were out of scope for this release. They remain valid improvements.

4. **Content-addressed skip detected the shape change correctly.** The skip logic compared the new assembly configuration (79 features) against the existing provenance (75 features), found a mismatch, and triggered a full rebuild. This is exactly the behavior ADR-041 was designed for — skip when nothing changed, rebuild when something did.

5. **SHDI first-run was uneventful.** The SHDI pipeline ran viewpoint and compilation from cached raw data. No errors, no surprises. The fail-loud design (FileNotFoundError if raw data missing) was not triggered because v1.2.29 had already harvested SHDI.

6. **Remote verification expanded automatically.** The verification script detected 79 features (vs. 75 last time) and increased the comparison count from 300 to 316. No code change needed — it adapts to the feature count.

### What we'd do differently

1. **Add per-step duration logging to `refresh_pipeline.sh`.** Still not implemented (v1.2.29 item 2). We know the total was 25,860s but can only estimate per-step times from the status page timestamps. Adding `date +%s` before and after each step, with a summary table at the end, would make performance analysis precise.

2. **Log skip decisions to console, not just ledger.** Still not implemented (v1.2.29 item 3). When assembly forced a full rebuild, the only visible console output was the normal assembly progress. An explicit "Content-addressed skip: REBUILD (79 features vs. 75 in provenance)" line would make the postmortem trivial.

3. **Run the deploy-readiness falsification audit as a standard pre-deploy step.** We did it this time manually (`/falsify "we are ready to deploy"`). It should be a checklist item in the deployment guide.
